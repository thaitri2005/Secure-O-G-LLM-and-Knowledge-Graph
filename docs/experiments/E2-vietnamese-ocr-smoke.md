# E2: Vietnamese OCR smoke test

Later work: [E5](E5-ocr-engine-benchmark.md) compares OCR engines and [E8](E8-ak3-appendices-corpus-run.md) exercises a real appendix corpus. The current generic pipeline uses VietOCR by default; the EasyOCR observations below remain this experiment's historical results.

| | |
|---|---|
| **Date** | 24–25 October 2026 |
| **Question** | Does the opt-in Vietnamese–English OCR profile carry a scanned Vietnamese page through the normal ingestion pipeline with valid provenance? |
| **Requirement** | SR-12 (Vietnamese material), FR-14 (OCR evaluated before production use) |
| **Input** | A synthetic, image-only PDF of seven printed Vietnamese and English lines, generated by [`scripts/ocr_smoke.py`](../../scripts/ocr_smoke.py) |
| **Configuration** | [`configs/ingestion/vietnamese.json`](../../configs/ingestion/vietnamese.json): EasyOCR `vi` + `en`, auto mode, confidence threshold 0.5; CPU |
| **Outputs** | Ignored, local: `data/interim/ocr_smoke/` (PDF, reference, `metrics.json`) and `data/interim/runs/ocr_vi_smoke/` (bundle) |
| **Status** | Integration works. Not evidence of production-quality Vietnamese recognition |

How to install the OCR extra and run OCR on real documents is in the [OCR ingestion guide](../components/ocr-ingestion.md).

## Method

The script renders the reference lines onto a 1600 × 2000 image, saves it as an image-only PDF, registers it, and ingests it with the Vietnamese profile as named run `ocr_vi_smoke`. It then scores the canonical text against the reference with `graph_builder.ingestion.ocr_metrics.score_ocr`. The metric normalizes Unicode to NFC and whitespace, and keeps case, digits and Vietnamese diacritics.

```powershell
.\.venv\Scripts\python -m graph_builder.ingestion.ocr_models --languages vi en   # once, while online
.\.venv\Scripts\python scripts/ocr_smoke.py --run
```

On non-Windows hosts, pass `--font` with a font that supports Vietnamese.

## Results

| Date | Check | Result |
|---|---|---|
| 24 October 2026 | Unit tests | 96 passed; one cached-corpus regression skipped (fixture absent) |
| 24 October 2026 | Real CPU run of the image-only fixture | Conversion 51.6 s; artifact validation passed (one expected warning: no tables); end-to-end CER 10.5% (21/200 characters), WER 19.51% (8/41 words) |
| 25 October 2026 | Unit tests after review | 99 passed; one cached-GDR regression skipped (conversion fixtures absent) |
| 25 October 2026 | Published baseline and saved OCR output | All nine baseline artifact hashes and schemas verified. The saved OCR output re-validated with exact canonical offsets, valid bounding boxes and deterministic repeated chunking. No new accuracy benchmark was run |

## Interpretation and limits

- The CER and WER include chunking effects, not only recognition errors: the title became section metadata instead of body text. The degree symbol was misread, and some punctuation was lost.
- One clean, printed, synthetic page says nothing about handwriting, skew, poor resolution, complex reading order, merged table cells or real VPI scans.
- Vietnamese delivery is deferred under the English-first scope (D-27). Before that extension is prioritized, run a follow-up on representative scans with human reference transcriptions, separating clean/degraded scans, mixed pages, tables and numbers with units. The current workload evaluates English well reports.
