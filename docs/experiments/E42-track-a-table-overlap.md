# E42 — Removing proved hourly table overlaps from retrieval

The optional `--table-overlap` QA check projects a retrieval view from an existing K1 release. It uses the authoritative hourly tables from E41 and the verified native conversion cache. A complete native text span or body cell is eligible when its source box is inside the table, the same text appears in a source-backed row or caption, and the page and report context agree. The projection keeps the authoritative table and any adjacent native cells. The QA ledger records the original chunk, retained table and removed span offsets or cell coordinates. [Projection](../../src/graph_builder/corpus/qa/table_overlap.py)

## Results

Both profiles use exactly the same E41 K1 release, fidelity checks, cross-representation QA and form-overlap projection. The candidate adds the table-overlap check.

| Measure on the 229-page corpus | Before | After |
| --- | ---: | ---: |
| Surplus occurrences of numbers also found in the source | 14,374 | 11,148 |
| Numeric occurrences matched against the page text layer | 47,627/48,072 | 47,616/48,072 |
| Word occurrences matched against the page text layer | 94,037/96,028 | 94,007/96,028 |
| Pinned phrases | 1,266/1,271 | 1,266/1,271 |
| Pinned structured table cells | 47/47 | 47/47 |
| Ordered Palm Valley time pairs | 624/624 | 624/624 |

The projection removes 881 native text spans and 336 rendered body cells across 34 Palm Valley pages. The independent page-token check finds zero lost source word or numeric types. Amounts in the occurrence metric can fall when a removed duplicate had made up for a same-token occurrence missed elsewhere on the page. Every authoritative hourly chunk and K1 release file is identical across the profiles. The 170 pages from other report families and the separate 40-page Volve cohort produce identical retrieval chunks.

On Palm Valley page 30, the string `6:00 11:00 [ 2 ] Drilled` is removed from the compound table's retrieval text. The standalone hourly table retains `6:00 → 11:00`, and the neighboring `DIESEL (L) 4900` still appears in the same compound table chunk as before. The canonical K1 chunk remains available for inspection through its original ID. [Pinned time rows](../../configs/benchmarks/track_a_hourly_palm.json)

## Reproduction

Point the benchmark at the validated E41 candidate release under `data/interim/track-a-scale/corpus/exports/scale-hourly_operations/releases/`.

```sh
python scripts/benchmark_table_overlap.py \
  --pdf-dir data/raw/track-a-scale --corpus data/interim/track-a-scale/corpus \
  --release "$RELEASE" --hourly-reference configs/benchmarks/track_a_hourly_palm.json \
  --out data/interim/track-a-table-overlap/final-regression
```

The benchmark writes gate decisions, scores, timings and the two retrieval views. The development run pointed `GRAPHRAG_K1_RETRIEVAL_CHUNKS` to the view generated by `corpus qa --form-overlap --table-overlap` in the separate development checkout.
