# Papers, standards and supporting sources

Paper versions, PDF hashes and retrieval outcomes are in `results/literature.json`; short page-specific evidence is in `results/literature.json`. Numerical results below are the authors' results on their datasets, not measurements on the selected source pages. No additional benchmark or industry dataset was downloaded. Repository citations resolve through `configs/inputs.lock.json`; raw specification/model files resolve through `configs/inputs.lock.json`.

## Tables and continuity

**PubTables-v2, arXiv:2512.10888v3.** Pages 13-14 describe a separate ViT continuation classifier followed by table merging; Table 6 reports dots.ocr GriTSCon increasing from 0.5768 to 0.6844. This supports investigating an explicit assembly stage, but does not establish that deterministic header/column rules alone suffice. It also separates single-page extraction from full-document continuity. Evidence: `results/literature.json` (pubtables-v2, p14), `results/literature.json`; repository/model discussion in `docs/tools/potatr.md`.

**POTATR, arXiv:2606.09788v1.** This is a 29M page-level image-to-graph model, with spatially grounded nodes and external word/OCR input. Cross-page merging is a compositional extension, not the 29M model's demonstrated primary task. The lightweight model is relevant to CPU-constrained investigation, but its paper throughput is not a laptop measurement. Evidence: `results/literature.json` (potatr, pp1-2); `third_party/potatr/src/potatr/inference.py:98-145` and `:185-205`; MIT weight card `third_party/models/potatr/README.md:1-10`.

**Table Transformer.** Its models and GriTS evaluation are a useful foundation for comparing table structure and content independently of Markdown rendering. This study reads the code/documentation and does not download its dataset or run its model. Evidence: `third_party/table-transformer/README.md:1-35`; MIT code licence `third_party/table-transformer/LICENSE:1-21`; `docs/tools/table-transformer.md`.

**MonkeyOCR v1.5, arXiv:2511.10390v2.** Section 2.4 (p7) distinguishes table types for cross-page and cross-column merging. The useful lesson is to represent continuation direction and structure explicitly, rather than concatenate all neighboring tables. No MonkeyOCR weights or deployment were tested. Evidence: `results/literature.json` (monkeyocr), `results/literature.json`.

**LingDT-VL-OCR, arXiv:2603.11044v2.** The retrieved revision is titled LingDT-VL-OCR, replacing the earlier Agentar-Fin-OCR name in the source list. It describes cross-page contents consolidation, global heading reconstruction and a CellBBoxRegressor. These are separate problems: joining content does not establish a correct heading tree or cell grounding. Evidence: `results/literature.json` (agentar-fin-ocr, pp1,3), `results/literature.json`. Financial-document claims are not drilling-report or Vietnamese validation.

**TableParseMap, arXiv:2608.09842v1.** The paper reports 916 difficult tables, nine failure types and a best evaluated score of 85.03 TEDS, and proposes a decompose/enhance/correct controller with visual consistency checks. It motivates component-specific error labels and rollback checks; no controller was run within the local model budget. Evidence: `results/literature.json` (tableparsemap, pp1-2), `results/literature.json`.

**Marker.** Study the processor and continuation-direction ideas only. The pinned code LICENSE is Apache-2.0, correcting the earlier GPL attribution; weight rights are separate. The LLM merge processor distinguishes bottom/right continuation. Evidence: `third_party/marker/LICENSE:1-25`; `third_party/marker/marker/processors/llm/llm_table_merge.py:19-70`; `docs/tools/marker.md`. No code is reused and no weights are executed.

## Forms and retrieval

**Identify, Locate, Link (SmolDocling key-value extraction), arXiv:2608.20868v1.** The paper extends DocTags with key/value/region/link tags in a 256M model, coupling field detection, location and association. Its first page says weights will be released after publication; this study therefore does not treat it as an available, licensed deployment candidate. Evidence: `results/literature.json` (smoldocling-kv, p1), `results/literature.json`. This is closer to grounded form extraction than JSON-only templating, but daily-report transfer remains untested.

**AWS Textract schema.** The pinned SDK schema separates KEY/VALUE entity types, relationships, geometry and merged-cell spans. This is a useful representation reference, without using the paid cloud service. Evidence: `third_party/aws/botocore/data/textract/2018-06-27/service-2.json:883-905` and `:2395-2408`; pin in `results/upstream-snapshot.json`; Apache-2.0 SDK licence `third_party/aws/LICENSE.txt:1-25`. captured API/clone failures are retained in retrieval evidence; the final read uses the botocore mirror.

**Azure Document Intelligence schema, API 2024-11-30.** A key-value pair links key/value elements and confidence; cells carry row/column spans and lists of bounding regions, each with a page number and polygon. Regions and text offsets should be represented separately. Evidence: `third_party/azure-di-schema/specification/ai/data-plane/DocumentIntelligence/stable/2024-11-30/DocumentIntelligence.json:2262-2295`, `:3668-3692`, `:4214-4355`; MIT specification licence `third_party/azure-di-schema/LICENSE:1-21`. No service call was made.

**PaddleOCR KIE.** The guide separates semantic entity recognition from relation extraction and supports training both tasks. The original LayoutXLM card records CC-BY-NC-SA-4.0, so Apache-2.0 PaddleOCR code rights cannot be generalized to every KIE weight. Evidence: `third_party/paddleocr/docs/version2.x/ppstructure/model_train/train_kie.md:12-32`; `third_party/models/layoutxlm/README.md:1-15`; `docs/tools/paddleocr.md`. Vietnamese form accuracy and rights to specific fine-tuned KIE weights remain unresolved.

**Structure-aware tabular chunking, arXiv:2605.00318v1.** STC retains row structure under a token budget and uses key-value row serialization; the abstract reports BM25 Recall@1 improving from 0.366 to 0.754. This supports evaluating row-aware chunks, but cannot establish the same gain for drilling reports, and the current pipeline already has row splitting and repeated headers. Evidence: `results/literature.json` (tabular-chunking), `results/literature.json`; baseline `src/graph_builder/ingestion/chunking.py:24`.

**Chonkie and LangChain parent retrieval.** Chonkie's table chunker supplies a row/token-budget comparison, while ParentDocumentRetriever separates retrieval chunks from returned parents. Neither abstraction establishes complete page reconstruction or stable identifiers without additional checks. Evidence: `third_party/chonkie/src/chonkie/chunker/table.py:17-57`; `third_party/langchain/libs/langchain/langchain_classic/retrievers/parent_document_retriever.py:11-28` and `:84-108`; corresponding repository notes and LICENSE files.

**Contextual retrieval and dsRAG.** The Anthropic article was not fetched because its host is outside the permitted network scope. The permitted dsRAG source provides a concrete auto-context reference: generated context should be stored as derived information, separately from verbatim extraction. Evidence: `third_party/dsrag/dsrag/auto_context.py:71-144`; MIT `third_party/dsrag/LICENSE:1-21`. This is a source-reading judgment, not a measured retrieval gain or a claim to have reviewed the inaccessible article.

## Intake, scale and evaluation

**Apache Tika and Dangerzone.** Tika's composite detector illustrates content-aware MIME detection; Dangerzone illustrates an isolated conversion boundary with restricted container execution and an image intermediate. Detection/repair and safe isolation answer different questions. Evidence: `third_party/tika/tika-core/src/main/java/org/apache/tika/detect/DefaultDetector.java:30-54`; `third_party/dangerzone/dangerzone/isolation_provider/container.py:29-66`. Tika is Apache-2.0; Dangerzone is AGPL-3.0 and idea-only. No adversarial document test was run.

**Docling with Ray and data-prep-kit.** The Red Hat article was not retrieved because its host is outside the permitted network scope; its quoted memory/latency numbers are not adopted as findings. The permitted source gives a concrete transform contract returning outputs plus statistics and supporting flush. Evidence: `third_party/data-prep-kit/data-processing-lib/python/src/data_processing/transform/binary_transform.py:19-57`; Apache-2.0 `third_party/data-prep-kit/LICENSE:1-25`; `docs/tools/data-prep-kit.md`. Ray scale, restart durability and multi-worker memory are open validation tasks.

**OmniDocBench.** The source documents block/span annotations, reading order, normalized edit distance and TEDS. These are useful evaluation dimensions, while specific drilling-field pairing, cross-page joins and source fidelity need their own assertions. Evidence: `third_party/omnidocbench/README.md:11-30`; code licence `third_party/omnidocbench/LICENSE:1-25`; `docs/tools/omnidocbench.md`. No benchmark dataset was downloaded; dataset rights are not inferred from code rights.

**MPDocBench-Parse, arXiv:2605.22100v2.** Its 433 documents/3,246 pages cover English and Chinese and evaluate truncated text/table merging, reading order and heading hierarchy. It reinforces the need for document-level evaluation beyond single-page TEDS, but supplies no Vietnamese evidence. Evidence: `results/literature.json` (mpdocbench, p1), `results/literature.json`.

**OmniParseBench.** The listed Datalab article was outside the permitted network scope and was not fetched. Page-level pass/fail assertions remain a study suggestion, not a verified characterization of that benchmark. An example appropriate to this corpus is preserving the observed ak3-daily-operations association of Days On Location with 1; evidence and the conflicting existing gold annotation are in `results/tool-survey.json`. Benchmark implementation and licence are unresolved.

**Label Studio.** Community image-region/transcription templates offer an annotation candidate, but the native PDF OCR template is explicitly tagged Enterprise. Do not infer that native PDF annotation is included in the Apache community edition. Evidence: `third_party/label-studio/label_studio/annotation_templates/community-contributions/ocr-invoices-pre-ner-bio-format/config.xml:4-23`; `third_party/label-studio/label_studio/annotation_templates/computer-vision/pdf_ocr/config.yml:1-16`; `docs/tools/label-studio.md`.

## Industry standards

**WITSML DrillReport.** The mirrored schema names reporting time bounds, status, bit/fluid records, survey stations and activities. These are vocabulary references for explicit source-field mappings, not authority to replace the extracted wording or units. Evidence: `third_party/witsml-schema/doc/Standards/energyml/data/witsml/v1.4.1.1/witsml_v1.4.1.1_data/xsd_schemas/grp_drillReport.xsd:45-50` and `:107-142`. Embedded Energistics terms at `obj_drillReport.xsd:11-17` are distinct from wrapper rights; agreement retrieval remains unresolved. No external structured dataset was acquired; BSEE remains the selected structured dataset (`configs/datasets/bsee_wells.json`).

**OSDU.** Read the pinned data-definitions mirror and its provenance/lifecycle guides, separating logical record identity, version and source lineage from PDF page identity. The common-resources schema includes a Source field, while the manifest groups records for ingestion; neither supplies cell-level extraction grounding by itself. Evidence: `third_party/osdu/Guides/Chapters/05-Provenance.md:1`, `third_party/osdu/Guides/Chapters/06-LifecycleProperties.md:1`, `third_party/osdu/Generated/abstract/AbstractCommonResources.1.0.0.json:70-80`, `third_party/osdu/Generated/manifest/Manifest.1.0.0.json:1`; pin in `results/upstream-snapshot.json`, Apache-2.0 `third_party/osdu/LICENSE:1-25`. Only schema/documentation files were fetched.

**Queiroz et al., SPE-223801-MS.** The existing repository bibliography identifies the daily-report ontology paper and prior access limitation (`docs/references.md:27-39`). Full text was not retrieved in this study, so no specific class, relation or result is attributed to it. Treat it as a follow-up vocabulary source, not verified evidence for a mapping. No dataset was downloaded.
